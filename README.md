# Portal

给自己片刻，去别处。

一个全屏的沉浸式窗口：转动手机看向星海或湖畔，手机姿态保留重力方向，前摄在本机估计眼位，画面响应头部的左右、上下移动。可以不授权，直接拖动浏览。

## 启动

使用 Node.js 22.12+ 或 24+。

```sh
npm ci
npm run dev
```

打开终端显示的 localhost 地址。桌面 localhost 可以申请摄像头；局域网 HTTP 手机地址只能用于无权限浏览。

模型与 WASM 已随项目提供。需要重新准备它们时执行 `npm run assets`；这一步需要访问 Google 官方模型存储。依赖升级后重新运行该命令以同步 WASM。

## 手机 HTTPS 调试

准备匹配电脑局域网 IP/主机名、且已被 iPhone 信任的开发证书。证书及私钥不要提交进仓库。运行：

```sh
PORTAL_HTTPS_KEY=/absolute/path/dev-key.pem PORTAL_HTTPS_CERT=/absolute/path/dev-cert.pem npm run dev
```

电脑和手机连接同一网络，在 iPhone Safari 打开 `https://电脑的局域网IP:5173`。证书域名/IP 必须匹配；对未受信任证书点“继续”不等于建立可用的安全环境。生产测试可使用受信任的 HTTPS 静态托管，但本仓库未自动发布到公网。

## 构建与验证

```sh
npm run build
npm run preview
npm test
```

静态发布目录为 `dist/`，从站点根目录提供即可。浏览器测试先执行构建，再运行：

```sh
npx playwright install chromium
npm run test:e2e
```

如果已经安装 Google Chrome，可以使用 `PORTAL_TEST_CHROME=1 npm run test:e2e`，无需下载 Playwright Chromium。

## 使用

- 全站文字禁止长按选择，并禁用长按菜单与原生图片拖拽；按钮点击、面板滚动和允许的全景拖动仍可用。
- 主屏幕画布以绝对定位铺满 100lvh 的页面容器；用户已在当前 iPhone 上确认底部黑条消失。“设置 → 性能数据”提供屏幕、页面、可见视口和画布边界尺寸，便于检查其他设备。

- “打开这扇窗”启用手机姿态与前摄；“先随便看看”直接拖动浏览。
- 眼位开启后，正对屏幕稍停片刻建立中心，再轻轻左右、上下移动头部。
- “随手机”开启时禁止手指拖动和方向键转向，轻触仍可唤出控件；关闭后恢复手动转向。等待姿态数据时也保持此互斥规则，权限拒绝则恢复拖动。
- 轻触唤出工具栏。“随手机”独立控制姿态，“设置”中可开关眼位、重新采样或进入浏览器支持的全屏。
- “回正”只重设水平朝向并清除拖动偏移，保留手机相对重力的俯仰与倾斜。
- 后台释放摄像头和传感器，返回后轻触恢复并重新采样眼位。
- iPhone Safari 分享菜单选择“添加到主屏幕”，从图标打开可减少浏览器工具栏。普通标签页无法强制隐藏系统栏；没有离线缓存。主屏幕模式的画布采用完整视口高度，根背景、启动背景及系统主题色统一为中性深色，避免紫色露底。若系统仍保留底部手势区域，网页不能保证让画面覆盖它。更新后请先完全关闭主屏幕应用再打开；若启动色仍旧，可移除旧图标后重新添加。

## 现在的视角算法

**手机方向：** 上一版把进入时的整个旋转记为零点，因此平放进入后再竖起，相当于又仰头了 90°。现在只记录水平方向作为参考，俯仰与倾斜始终保留相对重力的角度。平放时画面朝地面，拿到竖直位置时看向地平线；回正也不会把倾斜姿势当成直立。

这里使用浏览器融合后的设备姿态，不是对陀螺仪角速度自行积分。“绝对”指相对重力的倾斜；虚拟环境无需绑定地理北方，所以水平朝向仍可回正，也不额外申请磁力计。保留上一轮的四元数平滑、静止死区和异常读数抑制。

**固定视场角：** 当前固定为屏幕短边 60°，移除视角滑块，也不读取旧的视野设置。横竖屏保持相同短边角度。这比原先约 10° 的物理窗口开阔，同时避免用户拉到极宽视角产生更明显的边缘变形。透视投影与素材自身的失真仍然存在。

**眼位响应：** 前摄通过双眼中点、眼间距和近似相机视角估计位置。先用连续稳定的 10 帧建立中心（至少约 280 ms）；之后每个有效位置都参与计算，头部位移按 3 倍映射为屏幕局部偏移。每个像素的观看方向大致为：

```text
世界方向 = 手机与手动朝向 × normalize(屏幕像素位置 − 虚拟眼位)
```

眼位在局部屏幕坐标中计算，手机旋转只应用一次。取消眼位死区、大幅跳变丢弃和偏移限幅，采用位置与速度连续的临界阻尼跟随：每次新眼位到来时保留已有移动速度，避免逐次重新插值导致速度突变。不会额外缓存一整帧来等待插值。识别丢失时冻结最后显示的眼位偏移，不自动回中；恢复后沿用原中心继续跟随。

**连续跟随：** 摄像头目标 30 fps；优先在视频新帧到达后推理，Worker 目标 30 次/秒，主线程降级目标 15 次/秒。上一帧处理完成时，如果摄像头已有更新的画面，立即取最新帧；否则等待下一新帧，不积压、不额外等待一个完整采样周期。实际速度取决于手机性能；渲染独立平滑更新。

**减少顿挫：** 显示位置用临界阻尼弹簧的解析解更新，固定响应参数 ω=75/s。在固定目标、初始静止的测试中约 80 ms 达到目标位移的 98%，30/60/120 Hz 的固定目标响应一致；这不是相机到屏幕的端到端延迟指标。静止目标不产生反复弹跳，换向时先平滑减速再转向。实际识别噪声和设备帧率仍会影响真机观感。

**减少延迟：** 连续移动时用估计速度做最多 50 ms 的短期预测，预测额外偏移最多 0.1，不限制真实眼位移动范围。反向运动会重估速度，丢失识别后立即停止预测并保持位置。预测是近似，可能有少量超前，需真机反馈。

**性能数据：** 设置中展开“性能数据”，可看到渲染 fps、实际推理结果频率、平均处理耗时和 Worker/Main thread 模式。处理耗时包含帧拷贝与推理，不包含相机曝光与系统采集延迟；追踪频率也包括未找到人脸的结果。若仍卡顿，记录这些数据可帮助定位瓶颈。

**移动增益：** 固定使用 3 倍眼位位移响应，不增加视场角选项；移除了原来的 ±0.25 偏移上限和 ±250 mm 横向位置裁剪。有效识别到的大幅偏移也会参与计算。保持 60° 指基础投影与焦距不变，大幅离轴时实际可见角度与边缘透视仍会变化。这是增强响应的体验尝试，不等同于真实 3D。

**这一轮的限制：** 只恢复左右、上下眼位响应，前后移动不改变焦距，避免距离估计噪声造成忽大忽小。它是固定投影上的离轴偏移近似，尚不是按手机物理尺寸标定的完整窗口。全景也没有真实近远景视差或双眼立体画面。更详细的公式与参数见[技术架构](docs/architecture.md)。

## 验证边界

已修复一个实际的运行问题：MediaPipe 加载器使用 `importScripts()`，原来的 module Worker 不兼容，导致模型自动降到主线程。现在生产构建和开发服务器都使用经典 Worker；测试会确认实际执行模式，而不只是确认模型能加载。支持的设备在“性能数据”里应显示 Worker；不支持时仍可降级。

验证开发服务器的 Worker 路径可运行 `PORTAL_TEST_DEV=1 PORTAL_TEST_CHROME=1 npm run test:e2e -- --grep 'worker preferred'`。测试单独使用 4173 端口，不复用已有服务器。

本轮只进行代码与自动化测试。覆盖平放进入后拿起、回正保留重力、固定投影、眼位稳定采样、大幅侧移与丢失保持，以及摄像头权限、模型加载、主线程降级和后台/退出释放。合成视频只验证模型管线，不验证真人精度。

真机由用户测试反馈，重点比较眼位关闭和开启时的稳定性，以及平放进入、拿起、横竖屏、眼位重新采样和后台返回。没有自动推送或部署。
